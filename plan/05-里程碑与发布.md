## 四、发布流程（M6 顺序固定）

1. 全量回归：双解释器 pytest、生成器 `--check`、基准、干净 clone 复核。
2. 终态回写：`plan/00` 台账、`plan/05` DoD、`plan/06` 对照表、README 状态行。
3. 提交并推送 → CI 四矩阵绿。
4. 手工构建确定性源码包（`git archive` + `gzip -9n`），sha256 留档。
5. 用户确认后打 annotated tag → 推送 tag → 等 tag run 绿。
6. `gh release create <tag> <artifact> --notes-file plan/RELEASE-NOTES-M6.md`。
7. 发布后复核：`gh release view --json isDraft,assets`、真下载复算 sha256、中立目录解包冒烟。
8. 发布结果小提交回填（run id / release URL），推送等 CI 复绿，**不迁 tag**。

## 五、风险与缓冲

| 风险 | 缓冲 |
|---|---|
| 符号链接/权限样本跨平台行为不同 | 按文件系统实测能力跳过并记录，不按平台名硬编码 |
| Docker 真实环境不可用 | fixture 为验收主路径；真实调用只作可选增强 |
| Windows 长路径与文件占用 | 生成器与扫描器都走 `\\?\` 前缀；占用错误逐条记录 |
| 报告确定性受浮点/排序影响 | 全程整数字节 + 固定排序键 |
| 发布期 CI 首跑失败 | 预算至少一轮诊断；每棒双解释器全量复跑降低概率 |
