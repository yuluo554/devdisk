# 02 · 架构与技术选型 — DevDiskAudit

> 上游：`plan/01-题目文档.md`（需求与验收）、`data/README.md` §四（数值口径，唯一来源）。
> 本文只回答"怎么搭"，不重复题面论证；任何数值口径冲突以 `data/README.md` §四 为准。

## 一、目标与非目标（摘自 01，架构层只保留边界）

**目标**：一条命令完成 `扫描 → 分级 → 只读审计 → 显式清理 → 可撤销 → 单文件报告` 的本地闭环。

**架构层硬边界**：

- 纯本地：无服务器、无数据库服务、无网络请求、无遥测。
- 默认只读：`scan` / `audit` / `report` 不修改被扫描目录；`clean` 默认 dry-run。
- 删除只走隔离区：移动而非删除；`undo` 可逆。
- `.git` 只读：不删除、不移动、不执行 `git gc`；Docker 只调用 `docker system df`，不调用任何 prune。
- 首期只保证"扫描 + 隔离"在 Windows / Linux 主力平台可用；macOS 与系统级缓存留扩展项。

## 二、交付形态与运行边界

| 项 | 定案 | 理由 |
|---|---|---|
| 形态 | Python CLI + 本地单文件 HTML 报告 | 题面唯一形态；终端负责执行，HTML 负责阅读 |
| Python 底线 | 3.8 | 本机通道之一；CI 矩阵覆盖 3.8 / 3.12 |
| 运行时依赖 | **零第三方依赖**（标准库） | 离线可用、安装面最小、隐私面可审计 |
| 测试依赖 | `pytest`（仅 dev extra） | 干净环境按 README 一条命令装齐 |
| 可选外部程序 | `docker` CLI（只读调用） | 缺失时显式降级，不作为验收前置 |
| 打包 | 源码包 + `pip install` | 首期不做 exe/GUI；发布附件为确定性源码包 |

## 三、分层架构

```
┌─────────────────────────────────────────────────────────────┐
│ CLI 层  src/devdisk/cli.py                                  │
│   scan / audit / clean / undo / report                      │
│   只做参数解析、编排、退出码映射；零判定逻辑                  │
├─────────────────────────────────────────────────────────────┤
│ 编排层  src/devdisk/pipeline.py（M1 起）                     │
│   把 扫描 → 分级 → 审计 → 报告 串成可单独调用的公开函数组     │
├──────────────┬──────────────┬──────────────┬────────────────┤
│ 扫描层        │ 分级层        │ 审计层        │ 执行层          │
│ scanner.py   │ grader.py    │ audit/        │ quarantine.py  │
│ rules.py     │ evidence.py  │  docker.py    │ manifest.py    │
│              │              │  git.py       │ digest.py      │
├──────────────┴──────────────┴──────────────┴────────────────┤
│ 基础设施  serialize.py（确定性写盘）/ config.py / encoding.py │
├─────────────────────────────────────────────────────────────┤
│ 报告层  report.py（只消费既有结论，零重算、零外链）            │
└─────────────────────────────────────────────────────────────┘
```

**分层纪律**：

1. **CLI 零判定**：CLI 只解析参数与映射退出码；分级、体积、建议全部来自下层。
2. **报告零判定**：`report.py` 只读入 JSON 并渲染，不重新计算分级或体积；聚合值由输入算出。
3. **参照实现不共享**：基准用的独立参照实现放在 `tools/reference_grade.py`，生产模块禁止 import 它（AST 守门）。
4. **写盘单点**：所有 JSON 产物经 `serialize.write_json_atomic`，参数冻结（见 §六）。

## 五、CLI 契约

### 5.1 命令面

| 命令 | 用途 | 关键参数 | 产物 |
|---|---|---|---|
| `devdisk scan <root>...` | 扫描并分级 | `--out`、`--format json/csv`、`--min-bytes`、`--config` | 候选清单 JSON/CSV |
| `devdisk audit` | Docker / `.git` 只读审计 | `--root`（可重复）、`--docker`、`--git`、`--out` | 审计 JSON |
| `devdisk clean` | 选中项移入隔离区 | `--from`、`--select`（可重复）、`--apply`、`--yes`、`--trash` | 批次目录 + `manifest.json` |
| `devdisk undo <batch-id>` | 按 manifest 逆序移回 | `--trash`、`--yes` | 恢复结果 + 校验 |
| `devdisk report` | 生成单文件 HTML | `--input`、`--html`、`--audit` | 单个 `.html` |
| `devdisk --version` | 版本 | — | 一行版本号 |

**产品纪律**：不提供"全选/一键清理全部"参数；`clean` 未给 `--select`/`--from` 时拒绝执行。

### 5.2 退出码语义（单点定义在 `src/devdisk/exit_codes.py`）

| 码 | 名称 | 含义 |
|---|---|---|
| 0 | OK | 正常完成（找到或没找到候选都算完成） |
| 1 | REFUSED | 可预期的业务拒绝/冲突（如撤销目标已存在） |
| 2 | USAGE | 用法错误、未知命令/参数 |
| 3 | NOT_READY | 骨架期子命令尚未实现；**逐里程碑退役，退役后不得复用** |
| 4 | DEGRADED | 可选能力不可用（如 Docker CLI 缺失/输出无法解析） |
| 5 | UNSAFE | 安全拒绝（跨设备、越界路径、禁止操作） |

> 退出码 3 只存在于骨架期；plan/05 维护"退役表"，每个能力落地那一棒同轮删除旧断言并补离线冒烟。

### 5.3 标准输出约定

- 人类可读摘要写 `stdout`；错误与降级说明写 `stderr`。
- 机读产物只落 `--out` 指定的文件；不把 JSON 混进 stdout（便于管道与 CI 断言）。
- 所有面向用户的文案为中文；错误信息必须包含"下一步可做什么"。

## 六、数据契约与确定性

### 6.1 候选清单（`scan` 输出）

```json
{
  "schema_version": 1,
  "roots": ["<绝对路径>"],
  "generated_by": "devdisk <version>",
  "candidates": [
    {
      "path": "<绝对路径>",
      "type": "node_modules",
      "bytes": 123456,
      "mtime_utc": "2026-01-01T00:00:00Z",
      "project_root": "<绝对路径>",
      "is_symlink": false,
      "symlink_kind": "none",
      "file_count": 42,
      "directory_count": 7,
      "grade": "safe",
      "reason": "目录内仅有包管理器缓存结构，检测到 package-lock.json",
      "evidence": [{"kind": "lockfile", "path": "package-lock.json"}]
    }
  ],
  "skipped": [
    {"path": "<绝对路径>", "reason": "outside_root", "detail": "<可选：目标路径>"}
  ],
  "totals": {"candidate_bytes": 0, "by_type": {}, "by_grade": {},
             "other_bytes": 0, "other_count": 0, "skipped_count": 0, "ignored_count": 0}
}
```

- `totals` 由同一份候选清单计算，展示层不得二次四舍五入后求和。
- 排序固定：`bytes` 降序，同体积按 `path` 字典序（`data/README.md` §四 第 1 条）。
- 时间字段取文件系统 mtime 最大值，UTC ISO-8601（秒精度）；不写扫描时刻。
- **字段随里程碑落地**：M1 产出除 `grade`/`reason`/`evidence` 外的全部字段，
  这三项在 M1 恒为 `null`/`null`/`[]`（只出事实，不出判定）；M2 起填入真值。
- `project_root`：最近的项目标志文件所在目录；扫描根内找不到则为 `null`。
- `bytes` 为 0 的候选**不允许**出现：读不到的目录记 `skipped`，不伪装成空目录（K9 同源口径）。
- 跳过原因枚举：`outside_root` / `symlink_cycle` / `symlink_not_followed` /
  `permission_denied` / `duplicate_inode` / `not_directory` / `unreadable` /
  `in_use` / `ignored`。
- `symlink_kind`：`none` / `symlink` / `junction`。Windows 无符号链接权限时，
  生成器与扫描器都把 junction 视作"链接"，语义等价（都不跟随）。

### 6.2 审计输出（`audit`）

```json
{
  "schema_version": 1,
  "docker": {
    "status": "ok",
    "images": {"total_bytes": 0, "reclaimable_bytes": 0},
    "containers": {"total_bytes": 0, "reclaimable_bytes": 0},
    "volumes": {"total_bytes": 0, "reclaimable_bytes": 0},
    "build_cache": {"total_bytes": 0, "reclaimable_bytes": 0},
    "suggestions": [{"command": "docker image prune", "applied": false}]
  },
  "git": {
    "status": "ok",
    "repos": [
      {"path": "<绝对路径>", "objects_bytes": 0, "pack_files": 0, "loose_objects": 0,
       "suggestions": [{"command": "git gc", "applied": false}]}
    ]
  }
}
```

- Docker 缺失 → `status: "skipped:docker_unavailable"` + `reason`；解析失败 → `"error:docker_parse"`。
- `.git` 段只读；任何建议固定 `applied: false`。

### 6.3 隔离 manifest（`clean` 输出）

```json
{
  "schema_version": 1,
  "batch_id": "YYYYMMDD-HHMMSS-abcdef",
  "trash_root": "<绝对路径>",
  "source_root": "<绝对路径>",
  "created_from": {"mode": "select", "count": 1},
  "entries": [
    {
      "original_path": "<绝对路径>",
      "trash_path": "<绝对路径>",
      "bytes": 0,
      "grade": "safe",
      "reason": "...",
      "mtime_utc": "...",
      "tree_digest": "sha256:...",
      "status": "pending"
    }
  ]
}
```

- 状态机与批次命名只按 `data/README.md` §四 第 9/10/11 条执行。
- manifest 先写 `pending`，移动后写 `moved`；撤销逆序执行并逐条校验 digest。

### 6.4 确定性写盘

所有 JSON 经 `serialize.write_json_atomic`：

- `json.dumps(sort_keys=True, ensure_ascii=False, indent=2)`；
- UTF-8、`newline="\n"`、结尾一个换行；
- 原子写（同目录临时文件 + `os.replace`），中断不留下半个产物；
- 产物不含生成时刻/主机名/用户名（`data/README.md` §四 第 14 条）。

## 七、安全策略

| 风险 | 架构落点 |
|---|---|
| 跟随符号链接误伤系统目录 | `os.scandir` + `entry.is_symlink()`；不跟随；越界记 `outside_root` |
| 硬链接重复计数 | `(st_dev, st_ino)` 去重 |
| 跨设备移动破坏原子性 | 移动前比较 `st_dev`；不一致直接拒绝（退出码 5） |
| 撤销覆盖已有文件 | 目标存在即 `conflict`，停止该条，不覆盖 |
| 手删 `.git/objects` | 审计层只读；静态守门禁止 `git gc` / `git prune` 执行 |
| 误删手工文件 | 分级证据化；证据不足降 `caution`；默认 dry-run |
| 路径特殊字符破坏 HTML | 渲染统一 `html.escape`；零外链断言常驻 |

## 八、错误与降级语义

- **可恢复错误**（单个目录权限拒绝、文件被占用）：逐条记 `skipped:<reason>`，继续扫描，不中断整批。
- **可选能力缺失**（Docker）：`skipped:docker_unavailable` + 退出码 4；不得伪装成"没有可清理内容"。
- **解析失败**（Docker 输出格式变化）：`error:docker_parse` + 退出码 4；不填空值。
- **安全拒绝**（跨设备、越界、禁止删除项）：退出码 5 + 明确提示；不做"复制后删除"绕过。
- **撤销冲突**：退出码 1，逐条列出冲突路径，已完成条目保留并记录。

## 九、技术选型与弃选

| 选项 | 结论 | 理由 |
|---|---|---|
| 标准库 `os.scandir` + `hashlib` + `json` + `html` | ✅ 采用 | 零依赖、离线、可控 |
| 第三方遍历库（如 `pathspec`） | ❌ 弃 | 增加安装面；`.gitignore` 只需最小匹配子集 |
| SQLite 存审计历史 | ❌ 弃 | 首期无历史对比需求；JSON 足够且可审计 |
| 本地 Web 服务 / GUI | ❌ 弃 | 单文件 HTML 已满足阅读；省去端口与打包 |
| 直接 `shutil.rmtree` | ❌ 弃 | 不可逆；改为隔离区 + manifest |
| 调用 `git gc` / `docker prune` | ❌ 弃 | 写操作风险；只生成建议，`applied: false` |
| 读取源码/文档正文做判定 | ❌ 弃 | 隐私红线；只用路径、体积、mtime 与白名单元数据文件 |

## 十一、跨平台策略

- **Windows**：长路径统一 `\\?\` 前缀（仅绝对路径且长度超阈值时）；文件占用错误记 `skipped:in_use`；控制台编码由入口 `ensure_utf8_stdio()` 兜底。
- **Linux**：权限拒绝记 `skipped:permission_denied`；不扫描系统缓存目录。
- **macOS**：首期只保证扫描与隔离基本可用；`~/Library/Caches` 留扩展项。
- **Docker Desktop / WSL**：只审计当前 `docker` CLI 指向的上下文；WSL 发行版缓存留扩展项。

| 日期 | 偏差 | 结论与理由 |
|---|---|---|
| 2026-10-18 | `src/devdisk/` 新增 `model.py` / `rules.py` / `pipeline.py`（计划只列了模块名） | 分层需要：`model` 只放值对象、`rules` 只放规则加载与匹配、`pipeline` 放编排；三者都无副作用，便于单测与静态守门。 |
