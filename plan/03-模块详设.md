## 模块①：扫描与分类（M1）

### 输入

- `roots: list[Path]`（绝对化、去重、必须存在且为目录）
- 类型规则表 `data/rules/types.json`（随包，单点定义）
- 忽略规则 `data/rules/ignore.txt`（最小 `.gitignore` 子集：字面目录名、`*` 前缀/后缀、`/` 锚定）
- `candidate_min_bytes: int`（配置文件单点定义）
- 配置：`devdisk.toml`（可选）或 `--config`

### 输出

- `scan.json`：`candidates[]` + `skipped[]` + `totals{}`（契约见 plan/02 §6.1）
- `scan.csv`（可选）：列固定为 `path,type,bytes,mtime_utc,project_root,is_symlink,grade,reason`

### 关键实现

1. **遍历**：`os.scandir` 递归；每个目录先 `entry.is_symlink()` 判定，符号链接只记录不进入。
2. **去重**：`(st_dev, st_ino)` 集合；命中即记 `skipped:duplicate_inode`（保留首次出现）。
3. **类型识别**：规则表顺序匹配（`data/README.md` §四 第 3 条）；同一路径只取一个主类型。
4. **体积**：目录内所有普通文件 `st_size` 之和（`lstat`，不跟随）；不重复计硬链接。
5. **mtime**：目录内文件 mtime 最大值（UTC ISO-8601）。
6. **项目根**：从候选目录向上找最近的标志文件（`package.json` / `pyproject.toml` / `Cargo.toml` / `go.mod` / `pom.xml` / `build.gradle` / `*.csproj`），不越过扫描根。
7. **长路径**：Windows 上长度 ≥ 240 时加 `\\?\` 前缀（仅限绝对路径）。
8. **中断**：每处理完一个候选目录检查一次取消标志；已产出的部分结果不落盘（scan 是原子产物）。

### 失败与降级

| 情况 | 行为 |
|---|---|
| 根目录不存在/不是目录 | 退出码 2，列出非法根 |
| 子目录 `PermissionError` | 记 `skipped:permission_denied`，继续 |
| `OSError`（占用/IO） | 记 `skipped:<errno 名>`，继续 |
| 符号链接目标在根外 | 记 `skipped:outside_root`（仅当显式要求解析时；默认一律不跟随） |
| 符号链接环 | 因不跟随，天然不进入；若显式解析则 `skipped:symlink_cycle` |

### 验收基准

- 合成树 1000 个候选目录扫描不崩溃，耗时上限在基准里登记。
- 构造根外软链与软链环：断言候选清单不含根外路径、无死循环。
- 同树两次扫描 → `scan.json` 逐字节一致。
- 类型识别与体积合计对 `truth/manifest.json` 逐项一致。

### 里程碑

M1。

## 模块②：安全分级（M2）

### 输入

- 模块①候选清单
- 分级规则表 `data/rules/grades.json`（顺序固定）
- 白名单元数据文件清单（`.gitignore`、`package.json`、`package-lock.json`、`pyproject.toml`、`requirements.txt`、`poetry.lock`、`Pipfile.lock`、`Cargo.toml`、`go.mod`）

### 输出

每个候选增加：

- `grade`：`forbidden` / `caution` / `safe`
- `reason`：非空中文字符串（固定模板 + 变量，模板集中在 `grader.py` 常量区）
- `evidence[]`：`{"kind": ..., "path": ..., "detail": ...}`，至少 1 条

### 分级规则（顺序即优先级）

**禁止（forbidden）**

1. 路径本身是 `.git` 目录。
2. 路径等于任一扫描根。
3. 路径位于用户显式保留列表（`--keep` / 配置 `keep_paths`）。
4. 路径解析后越出扫描根（防御性；正常扫描不会产生）。

**谨慎（caution）**

5. 目录内存在 `.env`、`.env.*`、`*.local`、`*.pem`、`*.key`。
6. 构建产物目录（`dist`/`build`/`out`/`target`/`.next`）内存在 mtime 晚于构建标志文件的文件。
7. monorepo 共享依赖迹象：目录是符号链接，或被多个项目根引用（由候选清单的项目根集合推导）。
8. `.venv`/`venv` 内存在 `pyvenv.cfg` 之外的手工可执行配置（`bin/activate` 之外的 `.pth`/`.cfg` 自定义文件）。
9. 证据不足（无法确认可重建）。

**安全可删（safe）**

10. 缓存类（`__pycache__`、`.mypy_cache`、`.pytest_cache`、`.tox`、`.cache`）：纯缓存结构，且无第 5 条命中。
11. `node_modules`：存在锁文件或 `package.json` 的 `dependencies`/`devDependencies` 字段，且无第 5/6 条命中。
12. `dist`/`build`/`out`/`target`/`.next`：存在构建配置（`package.json` scripts / `Makefile` / `Cargo.toml` / `pyproject.toml`），且无第 6 条命中。
13. `.venv`/`venv`：存在锁文件或 `requirements.txt`/`pyproject.toml`，且无第 5/8 条命中。

**兜底**：未命中任何规则 → `caution`，理由 `"证据不足：未识别到可重建标志"`。

### 关键实现

1. 规则表是数据文件，命中顺序由 `order` 字段固定；引擎只解释，不写死规则。
2. 证据提取只读白名单文件名与 `stat`，不打开文件正文；`package.json` 只解析 JSON 顶层键是否存在。
3. `reason` 由模板生成：`"<结论>：<证据摘要>"`；模板与证据摘要都不含用户绝对路径之外的隐私内容。
4. 每条候选至少 1 条 `evidence`；若规则命中但无证据 → 降级 `caution`。

### 失败与降级

| 情况 | 行为 |
|---|---|
| 规则表缺失/格式错 | 退出码 4（`DEGRADED`），不静默用内置默认 |
| `package.json` 无法解析 | 该条证据缺失，记录 `evidence_error`，按无证据处理 → `caution` |
| 路径读取失败 | 该条 `caution` + 理由说明 |

### 验收基准

- 每条候选 `reason` 非空且 `len(evidence) >= 1`。
- 合成真值树中每个样本分级与 `truth/manifest.json` 的 `expected_grade` 一致。
- 证据不足样本（真值标 `insufficient`）全部落 `caution`。
- 同输入两次分级结果逐字节一致。

### 里程碑

M2。

## 模块③：Docker 与 `.git` 只读审计（M3）

### 输入

- `--docker`：可选，调用 `docker system df`
- `--git`：扫描根下的 Git 仓库列表（存在 `.git` 目录）
- 阈值配置：`git_gc_loose_threshold`、`git_gc_bytes_threshold`

### 输出

`audit.json`（契约见 plan/02 §6.2）。

### Docker 实现

1. `subprocess.run(["docker", "system", "df"], capture_output=True, text=True, timeout=30, encoding="utf-8", errors="replace")`
2. 解析固定列：`TYPE TOTAL ACTIVE SIZE RECLAIMABLE`；支持 `Images`/`Containers`/`Local Volumes`/`Build Cache` 四类。
3. 体积字符串解析：`1.234GB`、`123.4MB`、`0B`、`12.3kB` → 字节（1024 进制）。
4. `RECLAIMABLE` 形如 `1.2GB (45%)` → 取前半段字节。
5. 缺失/失败 → `status: "skipped:docker_unavailable"` + `reason`；解析失败 → `"error:docker_parse"` + 原始输出前 20 行（截断）。
6. 建议命令只生成：`docker image prune`、`docker builder prune`、`docker container prune`、`docker volume prune`，全部 `applied: false`。

### `.git` 实现

1. 定位 `.git`：目录（普通仓库）或文件（worktree/submodule，内容 `gitdir: ...`）——文件形态记 `skipped:gitdir_file` 并记录目标，不跟随统计。
2. 统计：
   - `objects/pack/*.pack` 字节和 + `pack_files` 计数
   - loose：`objects/??/*` 下普通文件数与字节和（`??` = 两位十六进制目录）
   - 不统计 `objects/info/`
3. 建议：`loose_objects > threshold` 或 `objects_bytes > threshold` → `{"command": "git gc", "applied": false, "reason": ...}`。
4. **前后快照**：审计前后对 `.git` 目录做 `(相对路径, size, mtime_ns)` 清单，断言完全一致；不一致则 `error:git_mutated`（退出码 5）。

### 失败与降级

| 情况 | 行为 |
|---|---|
| Docker 不存在 | `skipped:docker_unavailable`，退出码 4 |
| Docker 超时 | `skipped:docker_timeout`，退出码 4 |
| Docker 输出无法解析 | `error:docker_parse`，退出码 4，附截断原文 |
| `.git` 读取权限拒绝 | 该仓库 `skipped:permission_denied`，继续其他仓库 |
| `.git` 审计前后变化 | `error:git_mutated`，退出码 5 |

### 验收基准

- 固定 Docker 文本 fixture（至少 3 种版本形态）→ 四类体积与可回收量解析正确。
- 合成 Git 仓库（含 pack 与 loose）→ `objects_bytes`/`pack_files`/`loose_objects` 精确匹配。
- 审计前后 `.git` 文件清单与 mtime 不变。
- 静态守门：`src/` 中不出现执行 `git gc`/`git prune`/`docker * prune` 的调用。
- 输出中每条建议 `applied == false`。

### 里程碑

M3。

## 模块④：交互式清理与隔离区（M4）

### 输入

- 候选清单（`--from scan.json`）或显式路径（`--select`，可重复）
- 隔离区根（默认 `<scan_root>/.trash`，可 `--trash` 覆盖）
- `--apply`（缺省 dry-run）、`--yes`

### 输出

- `.trash/<batch-id>/` 下的移动后内容（保持相对路径结构）
- `.trash/<batch-id>/manifest.json`
- 批次摘要（stdout + 可选 `--out`）

### 关键实现

1. **默认 dry-run**：打印将移动的条目、目标路径、体积合计；不写任何文件。
2. **确认**：`--apply` 必须同时给 `--yes` 或在 TTY 下输入 `MOVE <batch-id 前缀>`；非 TTY 且无 `--yes` → 退出码 1。
3. **批次 ID**：`YYYYMMDD-HHMMSS-<6 位随机十六进制>`，UTC；冲突时重新生成（最多 5 次）。
4. **同文件系统校验**：`os.stat(source).st_dev == os.stat(trash_root).st_dev`；不一致 → 退出码 5，不复制。
5. **移动**：`shutil.move(src, dst)`；`dst` 为 `trash_root/<batch-id>/<相对扫描根的路径>`。
6. **manifest 状态机**：先写 `pending`（全部条目）→ 逐条移动并更新为 `moved` → 全部完成后写 `tree_digest` 并标记批次 `complete`。
7. **中断恢复**：下次启动时读 manifest，`pending`/`moving` 条目继续移动；`failed:*` 记录原因，不重试超过 3 次。
8. **撤销**：按 manifest 逆序；每条先算当前隔离路径的 digest，与 manifest 比对；目标路径已存在 → `conflict`，停止该条并继续其他条（或整体停止，由 `--stop-on-conflict` 控制，默认整体停止）。
9. **digest**：`sha256` over `relative_path\0size\0sha256(content)` 逐文件排序拼接。

### 失败与降级

| 情况 | 行为 |
|---|---|
| 选中路径不在候选清单且不是目录 | 退出码 2 |
| 选中项分级为 `forbidden` | 退出码 5，逐条列出 |
| 跨设备 | 退出码 5，提示改 `--trash` |
| 移动中 `OSError` | 该条 `failed:<reason>`，继续；批次结束退出码 1 |
| 撤销 digest 不匹配 | 该条 `conflict`，退出码 1 |
| manifest 缺失/损坏 | 退出码 2，不猜测 |

### 验收基准

- 撤销后原路径 tree digest 与移动前一致（逐字节）。
- 模拟中断（在 manifest 写 `moving` 后抛错）→ 恢复流程可完成或安全回退。
- 静态守门：`src/` 无 `shutil.rmtree`、无 `os.remove` 用于候选目录、无 `rm -rf` 字符串。
- `.trash/`、manifest、索引文件均被 `.gitignore` 覆盖（守门测试解析 `.gitignore`）。
- CLI 无"全选"参数（反射 `build_parser()` 断言）。

### 里程碑

M4。

## 模块⑤：本地 HTML 报告与真值基准（M5）

### 输入

- `scan.json`（必需）
- `audit.json`（可选）
- 隔离批次清单（可选）

### 输出

- 单个 `.html`：内联 CSS/JS，零外链，零网络请求。

### 页面结构（固定顺序）

1. 标题 + 一句话定位 + 数据来源（扫描根、生成参数）
2. 总览卡片：候选总数、候选总体积、可删合计（按分级）、跳过条目数
3. 体积排行（Top N，默认 50，可 `--top`）
4. 按类型聚合 / 按项目聚合（表格）
5. 分级分布（三级计数与体积）
6. 候选明细表（路径、类型、体积、mtime、分级、理由、证据）
7. Docker 段（含降级说明）
8. `.git` 段（含 `git gc` 建议与 `applied: false`）
9. 隔离批次与撤销说明（命令示例）
10. 免责声明：分级是建议而非保证

### 关键实现

1. 单一渲染源：`report.py` 从输入 JSON 计算聚合 → 渲染；页面内 JS 只做筛选/排序（不重算总量）。
2. 零外链断言常驻出口：生成后扫描 `<link href>`、`<script src>`、`url(http...)`、`@import`，命中即抛错。
3. `html.escape` 处理所有插值（路径、理由、证据）。
4. 确定性：不写生成时刻；`--as-of` 可选参数可固定展示时间（默认不显示）。
5. 输入缺失段（Docker 未审计）→ 显示"未审计"而不是 0。

### 失败与降级

| 情况 | 行为 |
|---|---|
| `scan.json` 缺失/坏 | 退出码 2 |
| `audit.json` 缺失 | 报告正常生成，Docker/.git 段显示"未审计" |
| Docker 降级 | 段内显式展示 `skipped:docker_unavailable` 与原因 |
| 输出路径不可写 | 退出码 2，不产生半成品（原子写） |

### 验收基准

- 断网双击打开可完整阅读（无外部 URL；测试断言 + 手工一次）。
- 总体积、各级合计、排行顺序与真值逐项一致。
- 同输入两次生成逐字节一致。
- 路径含 `<>&"` 的样本不破坏页面（转义断言）。
- 报告不出现"删除后必然安全"类承诺措辞（文案守门）。

### 里程碑

M5。

## 编排与 CLI（M1 起逐步接线，M5 收口）

- `pipeline.py` 暴露 `run_scan()` / `run_grade()` / `run_audit()` / `run_clean()` / `run_undo()` / `run_report()`；CLI 与测试都调用同一组函数（行为等价三方对账：CLI stdout = 编排直调 = 报告章节）。
- `cli.py` 只做 argparse + 退出码映射 + 中文错误文案。
- 每个子命令落地时：同轮退役 `NOT_READY` 断言 + 补一条离线 CI 冒烟。

## 模块间数据流

```
roots ──scan──> scan.json ──grade──> scan.json(带 grade)
                    │                    │
                    ├──audit──> audit.json
                    │
                    └──clean──> .trash/<batch>/manifest.json ──undo──> 恢复
                    │
                    └──report──> report.html（消费 scan/audit/batches）
```

**不变量**：

1. 任何阶段都不修改被扫描目录（`clean` 除外，且只移动选中项）。
2. 任何 JSON 产物可被下一阶段直接消费，不需要重新扫描。
3. 中间产物全部落 `--out-dir`（默认 `devdisk-out/`），可单步复查。
