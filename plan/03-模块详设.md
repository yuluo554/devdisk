# 03 · 模块详设 — DevDiskAudit

> 模块编号与 `plan/01-题目文档.md` §二 一一对应；数值口径引用 `data/README.md` §四，不另立。
> 每个模块写：输入 / 输出 / 关键实现 / 失败与降级 / 验收基准 / 里程碑。

## 模块①：扫描与分类（M1）

### 输入

- `roots: list[Path]`（绝对化、去重、必须存在且为目录）
- 类型规则表 `data/rules/types.json`（随包，单点定义）
- 忽略规则 `data/rules/ignore.txt`（最小 `.gitignore` 子集：字面目录名、`*` 前缀/后缀、`/` 锚定）
- `candidate_min_bytes: int`（配置文件单点定义）
- 配置：`devdisk.toml`（可选）或 `--config`

### 输出

- `scan.json`：`candidates[]` + `skipped[]` + `totals{}`（契约见 plan/02 §6.1）
- `scan.csv`（可选）：列固定为 `path,type,bytes,mtime_utc,project_root,is_symlink,grade,reason`

### 关键实现

1. **遍历**：`os.scandir` 递归，条目按名排序（保证遍历顺序确定 → 去重归属确定）；每个目录先判链接，链接只记录不进入。
2. **链接判定**：`lstat` 的 `S_ISLNK` **或** Windows reparse 属性（junction 与 symlink 同等对待，`symlink_kind` 区分）。判定顺序：环 → 根外 → 目标缺失 → 根内不跟随。
3. **去重**：目录按 `(st_dev, st_ino)`；文件仅对 `st_nlink > 1` 的硬链接去重（单链接文件不可能重复）。Windows 上 `DirEntry.stat()` 的 inode 恒为 0，缺 inode 时退回 `os.lstat`。
4. **类型识别**：规则表顺序匹配（`data/README.md` §四 第 3 条）；同一路径只取一个主类型，命中即**不再向下展开**（避免嵌套重复计数）。
5. **体积**：目录内所有普通文件 `st_size` 之和（`lstat`，不跟随）；不重复计硬链接。
6. **mtime**：目录内文件 mtime 最大值（UTC ISO-8601，秒精度）；无文件时退化为目录自身 mtime。
7. **项目根**：从候选目录向上找最近的标志文件（`package.json` / `pyproject.toml` / `Cargo.toml` / `go.mod` / `pom.xml` / `build.gradle` / `*.csproj`），不越过扫描根；找不到为 `null`。
8. **长路径**：Windows 上绝对路径长度 ≥ 240 时，对**文件系统调用**加 `\\?\` 前缀；输出路径保持普通绝对路径（便于用户直接使用与比对）。
9. **中断**：扫描是原子产物；不逐条落盘。取消标志由调用方在候选之间检查（M4 起接入 CLI）。

### 失败与降级

| 情况 | 行为 |
|---|---|
| 根目录不存在/不是目录 | 退出码 2，列出非法根 |
| 子目录 `PermissionError` | 记 `skipped:permission_denied`，继续 |
| 候选目录根读不到 | 记 `skipped:permission_denied` 并**不产出候选**（不伪装成 0 字节） |
| `OSError`（占用/IO） | 记 `skipped:<errno 名>`（`in_use` 单列），继续 |
| 链接目标在根外 | 记 `skipped:outside_root`，不跟随 |
| 链接环 | 记 `skipped:symlink_cycle`，不进入（链式解析最多 40 跳） |
| 链接在根内 | 记 `skipped:symlink_not_followed`，不跟随 |
| 规则表缺失/格式错 | 退出码 4（`DEGRADED`），静默退化被禁止 |

### 验收基准

- 合成树 1000 个候选目录扫描不崩溃，耗时上限在基准里登记。
- 构造根外软链与软链环：断言候选清单不含根外路径、无死循环。
- 同树两次扫描 → `scan.json` 逐字节一致。
- 类型识别与体积合计对 `truth/manifest.json` 逐项一致。
### 里程碑

M1。

## 模块②：安全分级（M2）

### 输入

- 模块①候选清单（含 `type` / `bytes` / `mtime_utc` / `project_root` / `skipped`）
- 分级规则表 `data/rules/grades.json`（顺序固定；**规则即数据**）
- 用户显式保留列表（`--keep` / 配置 `keep_paths`）
- 扫描产物的跳过记录（`skipped:symlink_not_followed` 的 `detail` 为目标路径，用于判"共享依赖"）
- 可打开的**白名单文件**只有 `package.json`（仅顶层键）；其余一律只读文件名与 `stat`

### 输出

每个候选增加：

- `grade`：`forbidden` / `caution` / `safe`
- `reason`：非空中文字符串 `"<结论>：<证据摘要>"`（模板随规则表给出；兜底与降级模板在 `grader.py` 常量区）
- `evidence[]`：`{"kind": ..., "path": ..., "detail": ...}`，至少 1 条；`path` 为相对路径（候选内→相对候选；项目根内→相对项目根；候选之外→相对扫描根）

`totals.by_grade` 从 M1 的空对象变为三级体积合计（三个键恒在，未出现的等级为 0）；
报告层的"可删合计"只累加 `safe` + `caution`，`forbidden` 永不进入可回收体积。

### 分级规则（顺序即优先级）

> 下表逐条对应 `data/rules/grades.json` 里的一条规则（括号内是规则 id）；
> **顺序即优先级**，命中第一条适用规则即返回。规则表是唯一来源（M2 起引擎零硬编码规则）。

**禁止（forbidden）**

1. 路径本身是 `.git` 目录（`forbidden:git_metadata`，类型 `git`）。
2. 路径等于任一扫描根（`forbidden:scan_root`）。
3. 路径位于用户显式保留列表（`--keep` / 配置 `keep_paths`）（`forbidden:keep_path`）。
4. 路径解析后越出扫描根（`forbidden:escapes_root`；防御性，正常扫描不产生）。

**谨慎（caution）**

5. 目录内存在 `.env`、`.env.*`、`*.local`、`*.pem`、`*.key`（`caution:local_state_file`）。
6. 构建产物目录（`dist`/`build`/`out`/`target`/`.next`）内存在**手工/本地文件**（`.env*`、`*.local`、`*.local.*`、`*.pem`、`*.key`、`config.*`），且其 mtime **晚于**目录内其他（产物）文件的最大 mtime，或目录内只有这类手工文件（`caution:manual_file_after_build`）。
   - 口径说明：比较基准是"目录内非手工文件的最大 mtime"（即最新构建产物），不是项目根的配置文件时间戳——否则任何正常产物都会误判。
7. monorepo 共享依赖迹象：目录自身是链接，或存在指向该目录的**根内链接**且引用方项目根与本目录项目根不同（`caution:shared_dependency`）。数据源是扫描产物的 `skipped:symlink_not_followed` 条目（`detail` 为目标路径）。
8. `.venv`/`venv` 内存在 `pyvenv.cfg` 之外、`bin/`/`Scripts/` 之外的 `.pth`/`.cfg` 文件（`caution:custom_venv_config`；只看文件名，无法区分是否包管理器生成，一律偏向谨慎）。

**安全可删（safe）**

10. 缓存类（`__pycache__`/`.mypy_cache`/`.pytest_cache`/`.tox`/`.cache`）：纯缓存结构，且无第 5 条命中。`__pycache__` 另要求目录内全部文件为 `.pyc`（`safe:pure_pyc`、`safe:pure_cache`）。
11. `node_modules`：项目根存在锁文件（`package-lock.json`/`npm-shrinkwrap.json`/`yarn.lock`/`pnpm-lock.yaml`/`bun.lockb`）或 `package.json` 顶层含依赖字段（`dependencies`/`devDependencies`/`peerDependencies`/`optionalDependencies`），且无第 5/6/7 条命中（`safe:node_modules_deps`）。
12. 构建产物目录的**证据按类型区分**，且无第 5/6 条命中：
    - `dist`/`build`（`safe:dist_build_config`）：项目根存在 `Makefile`/`pyproject.toml`/`setup.py`/打包器配置（`vite.config.*`/`webpack.config.*`/`rollup.config.js`/`esbuild.config.js`）/`tsconfig.json`/`build.gradle*`/`pom.xml`/`CMakeLists.txt`/`meson.build`，或 `package.json` 顶层含 `scripts`。
    - `.next`（`safe:next_build_config`）：项目根存在 `package.json` 或 `next.config.*`。
    - `out`（`safe:out_build_config`）：**只认** `package.json` 顶层 `scripts`。`Makefile`/`Cargo.toml` 的默认产出目录分别是 `build`/`target`，拿它们证明 `out` 可重建属于误判。
    - `target`（`safe:target_build_config`）：项目根存在 `Cargo.toml`。
13. `.venv`/`venv`：项目根存在锁文件或依赖清单（`poetry.lock`/`Pipfile.lock`/`uv.lock`/`requirements.txt`/`pyproject.toml`/`Pipfile`/`setup.py`/`setup.cfg`），且无第 5/8 条命中（`safe:venv_lockfile`）。

**兜底（第 9 条）**：未命中任何规则 → `caution`，理由 `"证据不足：未识别到可重建标志（…）"`；证据不足样本（真值标 `insufficient_evidence`）走这条路径。

### 关键实现

1. 规则表是数据文件，数组顺序即优先级（`order` 字段同事实显式声明，加载期校验两者一致且等级单调）；引擎只解释，不写死规则——守门测试断言规则表里的类型名与模式串**不作为字面量**出现在 `grader.py`/`evidence.py` 里。
2. 证据提取只读**文件名**与 `stat`，不打开文件正文；唯一允许打开的是白名单文件 `package.json`，且只解析顶层键（守门测试用运行期 `open` 记录断言：扫过的目录树里只打开过 `package.json`）。
3. 每个候选目录**只遍历一次**（流式聚合：命中清单、命中/非命中最大 mtime、文件计数、不可读目录），保证结果可复现且内存与目录规模无关。
4. `reason` 由模板生成：`"<结论>：<证据摘要>"`；模板随规则表给出（数据），只有"兜底"与"证据不足降级"两处模板固定在 `grader.py` 常量区。理由与证据 `detail` 只引用路径 / 体积 / mtime / 白名单文件名，不含任何文件正文内容，且不含绝对路径（证据 `path` 为相对路径）。
5. 每条候选至少 1 条 `evidence`；`safe` 必须过证据门槛：无证据、或候选子树存在读不全的目录 → 降级 `caution`（`grader._finalize`）。
6. 候选清单里 `forbidden` 与 `safe`/`caution` 分账：`totals.by_grade` 三个等级**恒在**（含 0），报告层的"可删合计"只累加 `safe` + `caution`。

### 失败与降级

| 情况 | 行为 |
|---|---|
| 规则表缺失/格式错 | 退出码 4（`DEGRADED`），不静默用内置默认 |
| `package.json` 存在但无法解析 | 该条证据缺失，记 `evidence_error` 证据，按无证据处理 → `caution` |
| `package.json` 不存在 | 该条证据缺失（不算错误，不记 `evidence_error`） |
| 候选子树存在读不全的目录 | 不得输出 `safe`，降级 `caution` 并在证据里给出不可读路径 |
| 路径读取失败 | 该条 `caution` + 理由说明 |

### 验收基准

- 每条候选 `reason` 非空且 `len(evidence) >= 1`（`tools/bench_grade.py` 常驻门）。
- 合成真值树中每个样本分级与 `truth/manifest.json` 的 `expected_grade` 一致（18 个候选样本逐项）。
- 证据不足样本（真值标 `insufficient_evidence`）全部落 `caution`。
- 同输入两次分级结果逐字节一致。
- **独立参照实现对账**：`tools/reference_grade.py`（不 import 生产模块、候选清单取自真值）逐样本结论一致。
- 变异验证：摘掉"证据不足降级"分支 → 常驻门变红（`tests/test_grader.py`）。

### 里程碑

M2。

## 模块③：Docker 与 `.git` 只读审计（M3）

### 输入

- `--docker`：可选，调用 `docker system df`；`--docker-fixture <file>` 用固定文本代替真实调用（离线验收主路径）
- `--root`（可重复）：`--git` 时的扫描根（必填）
- `--git`：扫描根下的 Git 仓库列表（存在 `.git` 目录或文件）
- 阈值配置：`git_gc_loose_threshold`、`git_gc_bytes_threshold`（`config.py` 单点默认值）

### 输出

`audit.json`（契约见 plan/02 §6.2）。

### Docker 实现

1. `subprocess.run(["docker", "system", "df"], capture_output=True, text=True, timeout=30, encoding="utf-8", errors="replace")`
2. 解析固定列：`TYPE TOTAL ACTIVE SIZE RECLAIMABLE`；支持 `Images`/`Containers`/`Local Volumes`/`Build Cache` 四类。
3. 体积字符串解析：`1.234GB`、`123.4MB`、`0B`、`12.3kB` → 字节（1024 进制）；小数部分用整数运算截断。
4. `RECLAIMABLE` 形如 `1.2GB (45%)` → 取前半段字节。
5. 缺失/失败 → `status: "skipped:docker_unavailable"` + `reason`；超时 → `"skipped:docker_timeout"`；
   解析失败 → `"error:docker_parse"` + 原始输出前 20 行（截断）。
   只有表头（无数据行）是合法输入 → 四类体积为 0；**有数据行却缺整类**按解析失败处理。
6. 建议命令只生成：`docker image prune`、`docker builder prune`、`docker container prune`、`docker volume prune`
   （只为可回收体积 > 0 的类生成），全部 `applied: false`。

### `.git` 实现

1. 定位 `.git`：目录（普通仓库）或文件（worktree/submodule，内容 `gitdir: ...`）——文件形态记 `skipped:gitdir_file` 并记录目标，不跟随统计。
2. 统计：
   - `objects/pack/*.pack` 字节和 + `pack_files` 计数（**不含** `.idx`）
   - loose：`objects/??/*` 下普通文件数与字节和（`??` = 两位十六进制目录）
   - 不统计 `objects/info/`
3. 建议：`loose_objects > threshold` 或 `objects_bytes > threshold` → `{"command": "git gc", "applied": false, "reason": ...}`。
4. **前后快照**：审计前后对 `.git` 目录做 `(相对路径, size, mtime_ns)` 清单，断言完全一致；不一致则 `error:git_mutated`（退出码 5）。
5. 仓库发现（`discover(roots)`）固定排序；命中 `.git` 后不再进入其内部继续找。

### 失败与降级

| 情况 | 行为 |
|---|---|
| Docker 不存在 | `skipped:docker_unavailable`，退出码 4 |
| Docker 超时 | `skipped:docker_timeout`，退出码 4 |
| Docker 输出无法解析 | `error:docker_parse`，退出码 4，附截断原文 |
| `.git` 读取权限拒绝 | 该仓库 `skipped:permission_denied`，继续其他仓库 |
| `.git` 审计前后变化 | `error:git_mutated`，退出码 5 |
| 未传 `--docker` / `--git` | 该段 `not_requested`；两段都未传 → 退出码 2 |

### 验收基准

- 固定 Docker 文本 fixture（新版 / 旧版 / 只有表头 / 畸形，4 种形态）→ 四类体积与可回收量解析正确；
  真值 `expect.json` 手写在 fixture 旁，不由解析器回填。
- 合成 Git 仓库（含 pack、loose、`objects/info` 与 `.idx` 干扰项）→ `objects_bytes`/`pack_files`/`loose_objects` 精确匹配。
- 审计前后 `.git` 文件清单（相对路径 + size + mtime_ns）不变。
- 静态守门：`src/` 中不出现执行 `git gc`/`git prune`/`docker * prune` 的调用。
- 输出中每条建议 `applied == false`。
- `tools/bench_audit.py` 双边门：fixture 逐字段 + `.git` 三值 + 误判 0 + 前后无变化。

### 里程碑

M3。

## 模块④：交互式清理与隔离区（M4）

### 输入

- 候选清单（`--from scan.json`）或显式路径（`--select`，可重复）
- 隔离区根（默认 `<scan_root>/.trash`，可 `--trash` 覆盖）
- `--apply`（缺省 dry-run）、`--yes`

### 输出

- `.trash/<batch-id>/` 下的移动后内容（保持相对路径结构）
- `.trash/<batch-id>/manifest.json`
- 批次摘要（stdout + 可选 `--out`）

### 关键实现

1. **默认 dry-run**：打印将移动的条目、目标路径、体积合计；不写任何文件
   （不创建隔离区、不创建批次目录、不落批次摘要；只有显式 `--out` 才写摘要）。
2. **确认**：`--apply` 必须同时给 `--yes` 或在 TTY 下输入 `MOVE <batch-id>`（完整 ID，
   防回车误触）；非 TTY 且无 `--yes` → 退出码 1，且不读终端（避免 `OSError`）。
3. **选择必填**：未给 `--select` → 退出码 1。`--from scan.json` 只提供候选上下文
   （`grade`/`reason`/`bytes`/`mtime` 来源），**不充当全选**。
4. **批次 ID**：`YYYYMMDD-HHMMSS-<6 位随机十六进制>`，UTC；冲突时重新生成（最多 5 次）。
5. **同文件系统校验**：`os.stat(source).st_dev == os.stat(trash_root 最近已存在祖先).st_dev`；
   不一致 → 退出码 5，**不复制**（不存在 `shutil.copy*` 回退路径，静态守门禁止）。
   dry-run 也做这项校验：早失败优于"预演通过、真跑失败"。
6. **隔离区可见性**：隔离区落在扫描根内时，其首层目录名必须被 `data/rules/ignore.txt` 命中
   （默认 `.trash`）；否则退出码 5（否则形成"清理 → 重扫又发现"的假循环）。
7. **移动**：`shutil.move(src, dst)`；`dst` 为 `trash_root/<batch-id>/<相对 source_root 的路径>`。
   选择项之间不得嵌套（父/子同时选中 → 退出码 2）。
8. **manifest 状态机**：先写 `pending`（全部条目）→ 每条先写 `moving` 并落 digest →
   移动 → 写 `moved`；全部完成后写批次级 `tree_digest` 并标记 `complete`；
   有失败则 `partial`（条目 `failed:<reason>`，取 errno 名）。
9. **中断恢复**：`clean --resume <batch-id>` 读 manifest：
   - 条目 `moved` → 跳过；
   - 条目 `moving` 且 `trash_path` 已存在、源已消失 → 补记 `moved`（"已移动但没来得及写"）；
   - 其余 `pending`/`moving` → 继续移动；`failed:*` 保留原因，不自动重试。
   预演（不带 `--apply`）只打印将要处理什么，不移动。
10. **撤销**：按 manifest **逆序**；每条先算隔离路径的当前 digest 与 manifest 比对
    （不一致 → `conflict`，不恢复），再检查目标路径 `lexists`（存在 → `conflict`，不覆盖），
    移动后重算 digest 再比对（不一致 → `failed:digest_after_restore`）。
    默认整体停止（`--stop-on-conflict`），可用 `--continue-on-conflict` 处理其余条目。
11. **digest**：见 `plan/02` §6.3.1（类型前缀 + 相对路径 + 字节数 + 内容 sha256，
    排序拼接；含空目录与链接目标，不含 mtime）。

### 失败与降级

| 情况 | 行为 |
|---|---|
| 未给 `--select`（且不是 `--resume`） | 退出码 1，明确提示"不提供全选" |
| 选中路径不在候选清单且不是目录 | 退出码 2 |
| 选中目录不在候选清单（但在盘上） | 现场扫描父目录重新分级；仍无证据 → `caution` 兜底，不默认 safe |
| 选中项分级为 `forbidden` | 退出码 5，逐条列出（`.git` 永不参与清理） |
| 跨设备 | 退出码 5，提示改 `--trash`；不复制 |
| 隔离区位于选中项内部 / 选中项位于隔离区内 | 退出码 5 |
| 选择项互相嵌套 | 退出码 2（拒绝，不重复移动） |
| 隔离区在扫描根内但未被忽略 | 退出码 5 |
| `--apply` 无 `--yes` 且非 TTY | 退出码 1，不读终端 |
| 移动中 `OSError` | 该条 `failed:<reason>`，继续；批次结束退出码 1 |
| 撤销 digest 不匹配 / 目标已存在 | 该条 `conflict`，退出码 1，不覆盖 |
| manifest 缺失/损坏/批次不匹配 | 退出码 2，不猜测 |
| `--resume` 与 `--select` 同用 | 退出码 2 |

### 验收基准

- 撤销后原路径 tree digest 与移动前一致（逐字节）。
- 模拟中断（在 manifest 写 `moving` 后抛 `KeyboardInterrupt`）→ `--resume` 可完成；
  在 move 之后、写 `moved` 之前中断 → 恢复时按 `trash_path` 补记 `moved`。
- 静态守门：`src/` 无 `shutil.rmtree`、无 `os.remove` 用于候选目录、无 `rm -rf` 字符串、
  无 `shutil.copy*`（跨设备不得用复制绕过）。
- `.trash/`、manifest、索引文件均被 `.gitignore` 覆盖（守门测试解析 `.gitignore`）。
- CLI 无"全选"参数（反射 `build_parser()` 断言 + 源码语义断言）。
- `tools/bench_clean.py` 常驻门：往返回归（digest 一致）+ 中断恢复 + dry-run 只读
  + 未选择退出码 1 + 清理后重扫不把隔离区当候选。

## 模块⑤：本地 HTML 报告与真值基准（M5）

### 输入

- `scan.json`（必需）
- `audit.json`（可选）
- 隔离批次清单（可选）

### 输出

- 单个 `.html`：内联 CSS/JS，零外链，零网络请求。

### 页面结构（固定顺序）

1. 标题 + 一句话定位 + 数据来源（扫描根、生成参数）
2. 总览卡片：候选总数、候选总体积、可删合计（按分级）、跳过条目数
3. 体积排行（Top N，默认 50，可 `--top`）
4. 按类型聚合 / 按项目聚合（表格）
5. 分级分布（三级计数与体积）
6. 候选明细表（路径、类型、体积、mtime、分级、理由、证据）
7. Docker 段（含降级说明）
8. `.git` 段（含 `git gc` 建议与 `applied: false`）
9. 隔离批次与撤销说明（命令示例）
10. 免责声明：分级是建议而非保证

### 关键实现

1. 单一渲染源：`report.py` 从输入 JSON 计算聚合 → 渲染；页面内 JS 只做筛选/排序（不重算总量）。
2. 零外链断言常驻出口：生成后扫描 `<link href>`、`<script src>`、`url(http...)`、`@import`，命中即抛错。
3. `html.escape` 处理所有插值（路径、理由、证据）。
4. 确定性：不写生成时刻；`--as-of` 可选参数可固定展示时间（默认不显示）。
5. 输入缺失段（Docker 未审计）→ 显示"未审计"而不是 0。

### 失败与降级

| 情况 | 行为 |
|---|---|
| `scan.json` 缺失/坏 | 退出码 2 |
| `audit.json` 缺失 | 报告正常生成，Docker/.git 段显示"未审计" |
| Docker 降级 | 段内显式展示 `skipped:docker_unavailable` 与原因 |
| 输出路径不可写 | 退出码 2，不产生半成品（原子写） |

### 验收基准

- 断网双击打开可完整阅读（无外部 URL；测试断言 + 手工一次）。
- 总体积、各级合计、排行顺序与真值逐项一致。
- 同输入两次生成逐字节一致。
- 路径含 `<>&"` 的样本不破坏页面（转义断言）。
- 报告不出现"删除后必然安全"类承诺措辞（文案守门）。

## 编排与 CLI（M1 起逐步接线，M5 收口）

- `pipeline.py` 暴露 `run_scan()` / `run_grade()` / `run_audit()` / `run_clean()` / `run_undo()` / `run_report()`；CLI 与测试都调用同一组函数（行为等价三方对账：CLI stdout = 编排直调 = 报告章节）。
- `cli.py` 只做 argparse + 退出码映射 + 中文错误文案。
- 每个子命令落地时：同轮退役 `NOT_READY` 断言 + 补一条离线 CI 冒烟。

## 模块间数据流

```
roots ──scan──> scan.json ──grade──> scan.json(带 grade)
                    │                    │
                    ├──audit──> audit.json
                    │
                    └──clean──> .trash/<batch>/manifest.json ──undo──> 恢复
                    │
                    └──report──> report.html（消费 scan/audit/batches）
```

**不变量**：

1. 任何阶段都不修改被扫描目录（`clean` 除外，且只移动选中项）。
2. 任何 JSON 产物可被下一阶段直接消费，不需要重新扫描。
3. 中间产物全部落 `--out-dir`（默认 `devdisk-out/`），可单步复查。
