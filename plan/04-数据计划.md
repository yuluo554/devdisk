## 二、合成目录树设计（M1）

### 2.1 生成器

`tools/gen_synth_tree.py --out devdisk-out/synth --seed 20261018 --check`

- 零第三方依赖；**自研确定性 RNG**（splitmix64），不用 `random`（跨版本序列不保证一致）。
- 所有文件 mtime 由生成器显式设定为固定时间戳，不取系统时钟。
- 同 seed 两次生成 → 目录树逐字节一致（文件内容、大小、mtime 均一致）。
- `--check`：生成到临时目录并与目标目录逐字节比对，不一致 exit 1。

### 2.3 真值台账结构

```json
{
  "schema_version": 1,
  "seed": 20261018,
  "generator_version": 1,
  "base_epoch_utc": "2026-01-01T00:00:00Z",
  "roots": ["."],
  "samples": [
    {
      "rel_path": "demo-web/node_modules",
      "type": "node_modules",
      "expected_grade": "safe",
      "expected_bytes": 1048576,
      "expected_mtime_utc": "2026-01-01T00:00:23Z",
      "project_root_rel": "demo-web",
      "evidence_facts": ["has_lockfile"],
      "note": ""
    }
  ],
  "scale_samples": [
    {"prefix": "demo-mono/pool/cache-", "count": 1000, "type": ".cache",
     "expected_bytes_each": 4096, "expected_bytes_total": 4096000, "note": ""}
  ],
  "skipped_expect": [
    {"rel_path": "demo-web/link-outside", "reason": "outside_root", "note": ""}
  ],
  "link_kinds": {"demo-web/link-outside": "junction"},
  "counts": {"sample_dirs": 19, "files": 1046, "total_bytes": 15644390}
}
```

**真值与引擎解耦**：

- 只记**事实**（类型、体积、mtime、是否存在某文件、是否软链），不记引擎的评分过程。
- `expected_grade` 是"规则应用后的期望结论"，由样本设计决定，不是从引擎输出抄来。
- 禁止出现 `observed_*` 一类字段（守门测试断言）。
- `expected_bytes` / `expected_mtime_utc` 由生成器按**自己写入的字节与设定时间戳**累加，
  不从扫描结果回填。

## 三、Docker fixture（M3）

`data/fixtures/docker_system_df/` 下每个文件 = 一次 `docker system df` 的完整 stdout：

| 文件 | 覆盖形态 |
|---|---|
| `v24_standard.txt` | 四类齐全，RECLAIMABLE 带百分比 |
| `v20_standard.txt` | 旧版列宽与单位（`MB`/`GB` 大写） |
| `empty.txt` | 只有表头，无数据行 |
| `malformed.txt` | 缺列 / 乱码，用于断言 `error:docker_parse` |

**纪律**：fixture 一律手写脱敏文本，不含真实镜像名/容器 ID；解析器只认字段名与列位置，不认具体数值。
手写真值 `expect.json` 与 fixture 同目录：四类 `total_bytes` / `reclaimable_bytes`、`status`
与建议命令清单逐项写死，**不由解析器回填**；畸形用例只登记 `raw_excerpt_limit`。

## 四、Git 合成仓库（M3）

- 生成器直接构造 `.git/objects/pack/*.pack` 与 `objects/??/*` 文件（不调用 git，避免环境依赖与 git 版本差异）。
- 真值记录：`objects_bytes`、`pack_files`、`loose_objects` 三个精确值（`truth/manifest.json` 的 `git_repos[]`）。
- 刻意放置的干扰项：`objects/pack/*.idx`（不计入字节与 pack 数）、`objects/info/packs`（整目录不计入）；
  另有一个 worktree 形态的 `.git` **文件**（`demo-infra/app/.git`），真值登记在 `gitdir_files[]`，
  审计必须是 `skipped:gitdir_file` 且统计全 0。
- 不使用真实 `git init`：CI 环境不保证 git 可用，且 git 版本会影响 pack 形态；合成结构已覆盖统计口径。
  "真实仓库形态兼容"留作扩展项，不作为验收前置。

## 五、报告基准（M5）

`data/truth/report_expect.json` 只存**从合成真值推导出的期望聚合值**：

```json
{
  "schema_version": 1,
  "source_truth": "devdisk-out/synth/truth/manifest.json",
  "expected_totals": {
    "candidate_bytes": 0,
    "by_grade": {"safe": 0, "caution": 0, "forbidden": 0},
    "by_type": {}
  },
  "expected_top_order": ["<rel_path>", "..."]
}
```

- 期望值由 `tools/gen_synth_tree.py` 同步产出（同一 seed、同一次运行），测试不手写。
- 报告测试用 `report --html` 生成后解析 HTML，断言数值与顺序；同时断言零外链。

## 六、数据生成与验收命令

```bash
# M1：生成合成树与真值（确定性）
py -X utf8 tools/gen_synth_tree.py --out devdisk-out/synth --seed 20261018
# 再生成一致性
py -X utf8 tools/gen_synth_tree.py --out devdisk-out/synth --seed 20261018 --check

# M1：扫描（样本体积都很小，必须显式把阈值降到 0，否则全部落进"其他"合计）
py -X utf8 -m devdisk scan devdisk-out/synth --out devdisk-out/scan.json --min-bytes 0

# M1：基准（双边门）
py -X utf8 tools/bench_scan.py --tree devdisk-out/synth

# M2：分级基准（分级一致 + 理由/证据充分 + 证据不足落谨慎）
py -X utf8 tools/bench_grade.py --tree devdisk-out/synth

# M2：独立参照实现对账（不 import 生产模块，候选清单取自真值）
py -X utf8 tools/reference_grade.py --tree devdisk-out/synth --scan devdisk-out/scan.json

# M3：只读审计（fixture 主路径 + 合成 .git 统计）
py -X utf8 -m devdisk audit --root devdisk-out/synth --git \
  --docker-fixture data/fixtures/docker_system_df/v24_standard.txt \
  --out devdisk-out/audit.json
py -X utf8 tools/bench_audit.py --tree devdisk-out/synth

# M4：隔离区往返基准（临时副本上重生成同一 seed 的合成树，不动本体）
py -X utf8 tools/bench_clean.py --tree devdisk-out/synth

# M5：报告
py -X utf8 -m devdisk report --input devdisk-out/scan.json --html devdisk-out/report.html
```

- [ ] 真值只存输入与期望，可由输入独立复算；无 `observed_*`。
- [ ] 生成器 `--check` 位级一致；产物不含时间戳/主机名。
- [ ] 入仓 fixture 不含真实路径、真实用户名、真实镜像名。
- [ ] 数值口径改动只发生在 `data/README.md` §四，并同步引用处。
